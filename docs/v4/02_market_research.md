# 02 市場研究：台灣大學生怎麼問課、問老師

撰寫日期：2026/10/18
配套檔案：`data/v4/query_bank_forum.jsonl`（248 筆測試 query）

## 1. 資料來源與方法

### 1.1 本地資料：Dcard 政大板志願序回報串

- 位置：`scheduling_test/data/dcard選課排幾txt/`，27 個檔案，涵蓋 108-1 到 114-2 每學期的一階、二階志願序回報集中串。
- 蒐集方式：檔案為整串貼文的純文字，看起來是從 Dcard 頁面整串複製下來。`scripts/crawl_dcard_nccu.py` 是另一支工具，用 Playwright 開 Dcard 政大板、攔截 `/api/v2/forums/nccu/posts` 回應，再以關鍵字（找課、求推、哪個老師、通識推薦等）與正規式抽出問句，輸出到 `data/raw/dcard_real_queries.jsonl`。這支腳本只處理前 50 篇相關文章，抽出的是片段，沒有分類。
- 規模：5,453 個非空行，其中 4,972 行是單筆回報（格式為 時段 課名 老師 開課單位 身分別 排幾上/沒上）。
- 我用簡單的正規式統計（腳本放在 `/tmp/mr_scripts/stats.py`，未進 repo）：

| 項目 | 行數 | 佔回報行 |

| 含「沒上」 | 1,621 | 33% |
| 含「不一定上」 | 271 | 5% |
| 一階或二階未滿 | 287 | 6% |
| 體育課（游泳、羽球、桌球、瑜珈等） | 538 | 11% |
| 註明身分別：外院／非本院 | 318 | 6% |
| 輔系 | 298 | 6% |
| 大四 | 316 | 6% |
| 本系本班 | 206 | 4% |
| 雙主修 | 163 | 3% |
| 學分學程 | 83 | 2% |

回報的志願序中位數是 3，最大到 28。分布為排 1 有 603 筆、排 2 有 1,257 筆、排 3 有 1,054 筆，排 10 以後合計不到 120 筆。多數串的格式說明寫明排 1 有上不用回報，所以排 1 的數字被低估，這份資料偏向記錄沒上或排很後面才上的案例。

這批資料只回答一種需求：這門課排第幾上得了。它沒有問句，不能拿來估計各類需求的比例，但可以說明志願序在政大是一個獨立而且份量很重的需求。

### 1.2 網路資料

共做了 30 多次搜尋與 20 次左右的頁面抓取。

- Dcard：直接抓頁面一律回 403，只能讀搜尋引擎的摘要。摘要可以看到政大板的選課心得文（甜、涼、推三項評分）、加簽規則集中串、114-1 選課心得的留言，以及成大、中山、北大、東海、逢甲、暨南、淡江等校的通識推薦文。
- PTT NTUcourse：ptt.cc 可以正常抓。我讀了看板首頁、以「問題」「請益」「推薦」「通識」搜尋的 9 頁結果，以及一篇評價文的發文模板。
- 課程評價工具：Chrome 線上應用程式商店與 chromeboard 的擴充功能頁、GDSC 政大課程評價網的 HackMD 期末簡報、OPT 歐趴糖的新聞報導、NTUCourse Neo 的 GitHub。
- 政大官方：通識架構表（統計系網站上的 PDF）、外語學院大學英文選課辦法。政大國際教育電子報與課程查詢說明的 PDF 連線被拒，沒有讀到。

### 1.3 需求比例怎麼估

主要樣本是 PTT NTUcourse 的提問標題。去掉公告、[News] 新課宣傳與已寫好的 [評價]/[通識] 心得文，再去掉重複的 Re/Fw，剩 149 則提問。我逐則人工標一個主要意圖：

| 主要意圖（PTT 標題，n=149） | 則數 | 比例 |
|---|---|---|
| 指定老師加課名，求整體評價（有人修過嗎、評價如何） | 70 | 47% |
| 課務瑣事（考試日期、直播連結、講義、課本、旁聽、課程異動） | 23 | 15% |
| 加簽方式、加簽機率、外系或外校能否加簽 | 13 | 9% |
| 同一門課不同老師或相似課程的比較 | 9 | 6% |
| 依主題求推薦（固態物理、理財、數學課、管理） | 5 | 3% |
| 實用性與修課規劃（後來才發現最實用的課、準大一修課方向） | 5 | 3% |
| 學分採計、免修、學程 | 5 | 3% |
| 先修與資格 | 3 | 2% |
| 明講甜、涼、Pass/Fail | 3 | 2% |
| 授課語言 | 2 | 1% |
| 上課形式（全線上、遠距） | 2 | 1% |
| 其他單項（衝堂、難度、出席、上課方式）與無法歸類 | 9 | 6% |

這個表只能當作論壇提問的樣貌。PTT 是台大的看板，使用者通常已經知道要修哪門課，才會用老師加課名發問，所以主題找課的比例偏低。標題裡的「評價」其實同時在問甜不甜、涼不涼、老師怎樣、考試作業怎麼安排；PTT 評價文模板的欄位就是：課程大概內容、上課用書、上課方式、評分方式（給分甜嗎？是紮實分？）、考題型式與作業方式、其它（出席、外系需要的基礎、老師個性、加簽習慣）。Dcard 心得文則固定用甜、涼、推（或收穫）三個分數。

因此下面第 2 節的比例是混合估計：以 PTT 標題為底，把「整體評價」拆回評價模板的各個面向，再依 Dcard 摘要中評分欄位與提問的出現頻率，以及政大志願序串的份量往上調整。數字是多標籤（一個問題可以同時屬於好幾類），加總超過 100%。這些都是估計值，誤差至少正負 5 個百分點。

## 2. 學生選課資訊需求分類

欄位名稱對應 `NCCUCourse/1142.db`：`COURSE`（name、info、objective、syllabus、schedule、evaluation、textbook、teaching_approach、ai_policy、time、point、kind、lmtKind、core、lang、note、unit、classroom 等）、`RATE.content`（官方教學意見調查的文字回饋，1142 版有 269,241 筆、涵蓋 31,612 個 courseId）、`RESULT`（studentLimit、studentCount、lastEnroll），加上學生自己的成績單。

| 代碼 | 類別 | 定義 | 估計佔比（助理情境，多標籤） |
|---|---|---|---|
| content | 內容與主題 | 想學某個主題或技能，不知道課名 | 約 30% |
| workload | 負擔（涼不涼） | 作業、報告、考試次數、分組、點名、閱讀量、課外時間 | 約 25% |
| grading | 給分（甜不甜） | 分數好不好拿、A 的比例、會不會當、調分、Pass/Fail | 約 20% |
| teacher_style | 老師風格與口碑 | 講課方式、個性、嚴不嚴、雷不雷、互動多寡 | 約 20%（含整體評價） |
| time | 時段與衝堂 | 星期、節次、早八、衝堂、想空出某天 | 約 15% |
| credit_req | 學分、通識類別、畢業條件 | 算哪一類通識、還缺幾學分、學程、輔雙認列 | 約 15% |
| popularity | 選不選得上 | 志願序要排第幾、一階會不會滿、加簽好不好加 | 約 15%（政大較高） |
| eligibility | 修課資格 | 年級、系所、身分別、先修、外系能不能修 | 約 10% |
| difficulty | 難度（硬不硬） | 內容深度、數學或程式門檻、容易被當 | 約 10% |
| comparison | 比較 | 同課不同老師、不同時段、相似課程之間怎麼選 | 約 10% |
| career | 實用性與生涯 | 對研究所、實習、證照、工作有沒有幫助 | 約 7% |
| language | 授課語言 | 英文授課（EMI）是全英還是混用、能不能用中文考 | 約 5% |
| format | 上課形式 | 線上、遠距、實體、半學期、暑修、旁聽 | 約 3% |
| logistics | 課務瑣事 | 課本、考試日期、考古題、異動 | 約 5%（多數超出系統範圍） |

### 2.1 各類說明、例句與可回答的資料

**content 內容與主題（約 30%）**

- 例句：想修跟行銷有關的課有推薦的嗎／有沒有教 Python 資料分析、文組也修得來的課／零基礎想學日文該選哪一門／有沒有講 ESG 永續的課／這門課實際上在教什麼，跟大綱差多少
- 資料：COURSE.name、info、objective、syllabus、schedule；RATE.content 可以補實際上課內容與大綱的落差。
- 備註：論壇上比例低，因為學生到論壇時多半已經有候選課。對一個搜尋助理來說，這會是最大宗的入口，v1 taxonomy 把主題加技能型估為 50%，我認為偏高，估 30% 左右。

**workload 負擔（約 25%）**

- 例句：有沒有不用分組報告的通識／這門會點名嗎，點名佔多少／求不點名只交期末報告的課／{老師}的課 loading 重嗎／想找涼一點的課塞學分
- 資料：COURSE.evaluation（評分項目與比例，常寫明出席扣分規則）、schedule、teaching_approach；RATE.content 偶爾會提到作業量；細節（點名頻率、雷組員）主要在學生評價。
- 備註：Dcard 摘要裡點名與分組幾乎每篇推薦文都會提到。有一則提醒老師沒有當眾點名、但用大頭照私下認人，表示點名方式本身也是資訊需求。

**grading 給分（約 20%）**

- 例句：有沒有甜一點的通識，大部分人 A 以上／{老師}給分甜嗎會不會當人／這門算紮實分還是很甜／求甜涼課不要點名／有沒有 Pass/Fail 又有趣的課
- 資料：COURSE.evaluation 只能回答評分方式，回答不了甜度；甜度需要學生評價或成績分布，政大目前沒有公開成績分布。
- 備註：台大有學生做了成績分布查詢的擴充功能，要先上傳自己的成績才能用，PTT 也有私下彙整成績分布的討論串，可見需求強烈。

**teacher_style 老師風格與口碑（約 20%）**

- 例句：{老師}人好嗎，上課會不會很無聊／唸投影片型還是會互動討論／想找老師很佛的課／{老師}很電嗎／上課可以用平板看電子課本嗎，怕老師介意
- 資料：COURSE.teaching_approach、ai_policy；RATE.content 是主要來源（例如老師講義脈絡清晰、實作太少、很願意讓學生討論）。
- 備註：PTT 近半數提問是老師加課名求評價，這類問題的答案大多落在老師風格。

**time 時段與衝堂（約 15%）**

- 例句：週三下午有什麼通識／不要早八，有沒有下午的體育課／週五想放假，哪些選修不在週五／一 D56 這個時段有沒有外院能修的課／{課}跟必修衝堂，有其他時段的班嗎
- 資料：COURSE.time（政大節次代碼如 D56、EFG）、classroom；學生已選課表可判斷衝堂。
- 備註：學生會直接用政大節次代碼發問，系統要能解析。教室在山上或山下也會影響排課。

**credit_req 學分與畢業條件（約 15%）**

- 例句：還差 4 學分社會通識有推薦的嗎／這門算人文通識還是跨領域／外系選修算不算畢業學分／大學英文抵免後要補什麼／依我修過的課畢業還缺哪些
- 資料：COURSE.point、kind、lmtKind（社會通識、外文通識、自然通識、跨領域等）、core（核心通識）；畢業條件要靠各系修業規定與學生成績單。
- 備註：通識架構依入學年度不同（109、112 學年度起各有一版），同樣的問題對不同年級答案不同。

**popularity 選不選得上（約 15%，政大偏高）**

- 例句：{課}排第幾比較有機會上／這門通識好搶嗎，一階排 3 會上嗎／有沒有冷門但不錯、一階不會滿的通識／{老師}加簽好加嗎，抽籤還是全簽／二階還有剩名額的課有哪些
- 資料：RESULT.studentLimit、studentCount、lastEnroll；Dcard 志願序回報（需要依身分別拆開）；加簽規則集中串。
- 備註：本地 27 串、近 5,000 筆回報是政大特有的資料。回報常寫成「本系排 4 上／外院排 3 沒上」，結果和身分別綁在一起，只給一個平均排名會誤導。

**eligibility 修課資格（約 10%）**

- 例句：外院可以修會計系的中級會計嗎／大一可以修大三的選修嗎／{課}一定要先修統計學嗎／我是雙主修，選得到{課}嗎／非本院可以選 EMI 的政治學概論嗎
- 資料：COURSE.note（備註）、lmtKind、subUnitRuleUrl、subSetUrl；學生的系級、身分（輔系、雙主修、學程）。

**difficulty 難度（約 10%）**

- 例句：計量經濟學很硬嗎，數學要多好／這門對沒程式底子的人會不會太難／民法總則好過嗎／想挑戰硬一點但學得到東西的課／個經哪個老師比較不硬
- 資料：COURSE.objective、syllabus 中的先修描述；主要靠學生評價。

**comparison 比較（約 10%）**

- 例句：統計學{老師A}跟{老師B}選誰，一個甜一個紮實／投資學跟財務管理哪個好修／同一門會計學開四個班差在哪／程式設計跟計算機概論內容重複嗎／必修沒抽到想要的老師，另一位會很慘嗎
- 資料：同課名不同 courseId 的 COURSE 欄位並排，加上各自的 RATE 與 RESULT。
- 備註：政大經濟、會計、統計、微積分等大班必修一開好幾班，志願序串裡同一門課常有五六位老師。

**career 實用性與生涯（約 7%）**

- 例句：想考經濟所，大學部先修哪些課有幫助／以後想當資料分析師有什麼課推薦／對找實習有幫助的課／這個學程對找工作有用嗎
- 資料：COURSE.objective；學程規劃文件；學生評價中的收穫分數。

**language 授課語言（約 5%）**

- 例句：有沒有英文授課但不太難的通識／寫 EMI，是全英文還是中英夾雜，考試可以寫中文嗎／不想修英文授課的，有中文班嗎
- 資料：COURSE.lang；實際使用程度要靠評價。

**format 上課形式（約 3%）**

- 例句：推薦全線上、不在意出席與分組的課／有沒有遠距或非同步的課／不要線上課／可以旁聽嗎
- 資料：COURSE.note、teaching_approach。

**logistics 課務瑣事（約 5%，多數不在範圍內）**

- 例句：要買哪本課本／期中考是哪一週／有考古題嗎／這學期有異動嗎
- 資料：COURSE.textbook、schedule 可以回答一部分；考古題與臨時異動不在資料內。

## 3. 政大和其他學校的差異

**政大**

- 志願序制度讓排第幾、身分別成為核心問題。回報格式固定為 時段 課名 老師 開課單位 身分別 排幾上/沒上，身分別包含本系本班、本系非本班、輔系、雙主修、本院外系、外院、大四、學分學程。
- 體育佔回報的一成以上，而且多半在問好不好選上，很少問內容。
- Dcard 政大板的心得文用甜、涼、推三個分數；GDSC 課程評價網與 Open NCCU 用甜、涼、收穫。
- 官方教學意見調查的文字回饋有公開，政大學生做的擴充功能（NCCU Course Rate Tool）直接拿它來顯示評價。其他學校比較少有這種官方文字回饋可以用。
- 學生習慣用政大節次代碼（一 D56、四 234、二 EFG）溝通。

**台大**

- PTT NTUcourse 有固定評價模板，提問以老師加課名為主。
- 加簽用授權碼，加簽習慣、加簽機率是常見問題。
- 成績分布是明確需求，有工具要求使用者上傳成績換取查詢權限。
- 工具最多：NTUCourse Neo（選課規劃）、台大課程評價小幫手（彙整 PTT、Dcard、NTU Rating）、NTU Course Search Helper（標示衝堂課）。

**其他學校（成大、中山、北大、東海、逢甲、暨南、淡江）**

- Dcard 以學長姐整理的通識推薦長文為主，評分維度多是涼度、甜度、推薦或收穫，北大有兩個數字的推薦指數。
- 求推薦的題目常加上條件：不點名、不分組、只有期末報告。
- 清大有清大選課助手，可一鍵連到 Dcard、NTHU MODS、歐趴糖查評價。

## 4. 用語對照

| 用語 | 意思 |
|---|---|
| 甜 | 給分高，多數人拿 A |
| 涼 | 負擔輕，作業考試少、不太需要花時間 |
| 甜涼課 | 又好拿分又輕鬆的課 |
| 硬 | 內容難、要求高、要花很多時間 |
| 紮實 | 內容多、學得到東西，常暗示不甜 |
| 電、被電 | 老師嚴格、考試難、會當人；被電指被當或被修理 |
| 大刀 | 當掉很多人的老師 |
| 佛、佛心、佛系 | 老師寬鬆，好過、給分好、不刁難 |
| 雷、踩雷 | 課或老師很差，修了後悔 |
| 雷組員 | 分組報告不做事的組員 |
| 水課 | 內容空洞、上了學不到東西 |
| 營養學分 | 很容易拿到的學分 |
| 歐趴 | all pass，全班都過 |
| 收穫 | 學到多少，Dcard 與評價網的第三個指標 |
| loading | 工作量 |
| 早八 | 早上 8 點的第一節課 |
| 排幾 | 一階志願序填第幾 |
| 一階、二階 | 政大選課的兩個階段，一階依志願序分發，二階處理剩餘名額 |
| 一階未滿 | 一階選完仍有名額，通常排多後面都上得了 |
| 不一定上 | 同一個排序有人上有人沒上，可能跟身分或點數有關 |
| 本系本班、外院 | 身分別，影響分發優先順序 |
| 加簽 | 開學後請老師額外核准選課 |
| 授權碼 | 台大的加簽碼 |
| 必帶班 | 台大大一英文的必修班 |
| 整開課 | 回報串用語，指學年課在上學期整批開放 |
| 擋修 | 沒修過先修課就不能選 |
| 開根號 | 調分方式之一，原始分數開根號乘以十 |

## 5. 學生目前用的工具與缺口

| 工具 | 涵蓋 | 主要缺口 |
|---|---|---|
| 政大全校課程查詢（qrysub） | 官方大綱、時間、限制、追蹤清單、教學意見 | 只能用課名、老師、系所等欄位查，無法用主題或條件找課 |
| 教務處推薦課程清單 | 通識中心每學期推薦 | 沒有評價與選上機率 |
| Dcard 政大板志願序回報串 | 每學期數百筆排幾上/沒上 | 純文字、格式不一、排 1 上不回報、身分別混在一起，每學期要重新翻 |
| Dcard 加簽規則集中串 | 各課加簽方式（全簽、抽籤、不加簽） | 同上，且老師每年可能改 |
| Dcard 心得文 | 甜、涼、推分數與文字心得 | 分散、只涵蓋少數熱門課；Dcard 擋爬蟲 |
| NCCU Course Rate Tool（Chrome 擴充） | 在課程查詢頁顯示 101-1 以來的官方評價、通識歷史初選排序、課表預覽 | 用課名加老師名比對，課名改了就找不到；官方評價多是正面短句（很好、無），看不出甜涼 |
| 政大開評器（Chrome 擴充） | 一鍵查網路評價與官方資訊 | 商店頁顯示約 158 位使用者，2024/08 後未見更新 |
| GDSC 政大課程評價網（course-nccu.com） | 使用者上傳的總分、甜、涼、收穫與文字心得 | 需要學生主動填寫，冷門課沒有資料；目前是否仍在運作未能確認 |
| Open NCCU／Open NCCU 排課系統 | 甜、涼、收穫加官方匿名評價、排課 | Notion 頁面無法讀取，功能與更新狀況未確認 |
| course.andyjjrt.cc（現有 CourseLangChain） | RAG 問答，輸出課表 | 未接評價與選上機率，條件過濾靠 LLM |
| 歐趴糖、UrSchool（跨校） | 甜度、涼度、收穫、考古題 | 以台大為主，政大資料少 |

共同缺口：

- 沒有工具能用主題加條件（時段、通識類別、身分、不要早八）一起找課。
- 評價資料以課名加老師名當鍵，跨學期換課名、合授、同名不同課都會出錯。
- 甜度和涼度只有零星學生評分，官方資料回答不了。
- 選上機率散在 Dcard 串，沒有依身分別整理，也沒有和 RESULT 的名額、最後錄取志願序結合。
- 沒有工具會讀學生的成績單，自動排除已修課、判斷還缺哪類學分、判斷身分。
- 評價沒有標時效，老師換教法或改給分後，舊評價會誤導。

## 6. 對系統功能與評測的影響

### 6.1 功能優先順序

1. 主題語意搜尋加硬條件過濾：時段（含政大節次代碼解析與否定，如不要早八、週五不要）、通識類別、學分、授課語言、身分可修。這是 content、time、credit_req、eligibility、language 幾類的交集，估計涵蓋一半以上的 query。
2. 評價摘要：從 RATE.content 抽出老師風格、負擔、點名、實作多寡等面向，標明來源學期與筆數。甜度要明說資料不足，不要用官方評價硬推。
3. 選上機率：用 RESULT（名額、選課人數、lastEnroll）加上志願序回報，依身分別給出區間，並把排 1 上被少報的偏差寫清楚。
4. 同課比較視圖：同課名不同老師或時段並排列出評分方式、時段、評價摘要、選上機率。
5. 成績單感知：排除已修課、計算缺的通識類別與學分、帶入系級與身分判斷資格。
6. 俚語與否定理解：甜、涼、硬、電、佛、雷、水課、loading 要能對應到評分方式、作業量、評價面向；不要、不想、避開要轉成排除條件。

### 6.2 建議測試情境

| 情境 | 說明 | query bank 中的對應 |
|---|---|---|
| 主題找課 | 模糊主題、跨系主題、技能型、錯字 | content，67 筆 |
| 否定與排除 | 不要早八、週五不要、不要分組、不要英文授課、不要線上 | notes 含 negation 或 query 含不要/不想/不用，約 38 筆 |
| 複合條件 | 三個以上條件同時成立 | need 有 3 類以上，35 筆 |
| 節次代碼 | 一 D56、二 EFG、二 34 | time 類 |
| 俚語 | 甜涼、電、佛、雷、水課、營養學分、大刀、loading | notes 標 slang |
| 身分相關 | 外院、雙主修、輔系、大四、學程對可修與選上機率的影響 | eligibility、popularity |
| 比較 | 同課多班、相似課程、替代課 | comparison，22 筆 |
| 需要成績單 | 依修課紀錄算缺學分、排除已修 | notes 標需要學生成績單 |
| 資料不足應拒答或保留 | 甜度、A 的比例、考古題、新開課評價 | grading、logistics、overall_review 中的部分 query |
| 關鍵字式短 query | 甜涼通識、統計學 哪個老師 | notes 標關鍵字式 |

評測上要注意：

- 有一類 query 系統應該回答不知道或只給部分資訊（成績分布、考古題、尚無評價的新課），要把正確拒答算進分數。
- 含 {老師}、{課} 的 query 是模板，評測時要用真實課程填入，並確認答案只引用資料庫中的內容，不能編造老師評價。
- popularity 類的正解要依身分別給，評測標註時要附上提問者身分。

### 6.3 query bank 分布與估計值的差異

248 筆中各類標籤比例：content 27%、credit_req 21%、workload 20%、grading 16%、eligibility 15%、teacher_style 15%、time 14%、popularity 12%、difficulty 11%、comparison 9%、career 7%、language 6%、overall_review 5%、logistics 4%、format 3%。政大情境 165 筆、改寫自台大 PTT 題型 52 筆、通用 31 筆。credit_req 和 eligibility 刻意比估計值多放，因為這兩類對應硬條件過濾，是目前系統最容易出錯的地方；grading 比估計值略少，因為能用資料回答的部分有限。

## 7. 限制

- Dcard 頁面無法直接讀取，Dcard 的部分只靠搜尋摘要，樣本小且可能偏向搜尋引擎收錄的熱門文。
- 比例估計的主樣本來自台大 PTT，用在政大要打折扣；政大特有的志願序需求是用本地回報串補上的，兩者無法用同一個分母比較。
- 標註由一人完成，沒有做第二人一致性檢查。
- 各評價網站與擴充功能的現況（是否仍在運作、使用人數）大多無法確認。
